# 大肥鱼开关 · 开发日志

> 项目：`大肥鱼开关.exe`（C++ / Win32 / 单文件）
> 源码：`main.cpp`（约 650 行，Unicode，静态链接）
> 开发日期：2026-11-11 14:33 – 15:10
> 当前版本：v0.4（2026-11-11 15:06 编译）

---

## 1. 要解决的问题

她的运行方式对普通人很不友好：

- **两个进程缺一不可**：大脑 AstrBot（6185）和登 QQ 的 NapCat（6199）。
- **启动有顺序**：NapCat 先起会一直 `ECONNREFUSED 127.0.0.1:6199` 刷屏，因为平台的 WS 还没在听；所以必须「先大脑 → 等它起来 → 再 NapCat」。
- **关闭也有顺序**：反着来（先关大脑）或者直接强杀，QQ 登录态容易失效，下次要重新扫码——表现为那句误导人的「文件已损坏，请重新安装 QQ」。
- 还要能「暂停开机自启」（不想让她开机就跑，比如出门/开会）。

于是做一个 **一键开关 + 暂停自启** 的小窗口工具。

## 2. 技术选型

| 选择 | 理由 |
|---|---|
| C++ / Win32 原生 | 用户点名要 C++；不引入 Qt/.NET 运行时，单文件 600 KB 左右，静态链接后不依赖任何 DLL |
| 不做服务/托盘 | 就是一个「打开点两下」的东西，最小可用 |
| **端口判断用 connect 探测，不用系统 TCP 表** | 这台机器的 `netstat`/`Get-NetTCPConnection` 报不出监听状态（同一端口一会儿 `Listen`、一会儿空、一会儿 `TimeWait`），按表判断会误报「没开」。**真连一次**才可靠（这条经验来自同一天修工作台补丁时踩的坑） |
| 小号是否在线，复用 Skill 的探针 `backend_state.py` | 它是全局口径（工作台、掉线提醒都用它），而且当天已修好端口误判；不自己另写一套 |
| 关进程用 `taskkill /F /T /IM <名字>` | `/T` 连子进程一起收；只按镜像名匹配，不会误杀桌面 QQ |
| 起进程用 `CreateProcessW` + `CREATE_NEW_CONSOLE` | 跟双击 .cmd 一样，各自有独立黑窗口，用户能看到日志 |

## 3. 环境准备

机器上**没有任何 C++ 编译器**（无 VS、无 MinGW、无 MSYS2）。

- 先试了 winlibs 完整包（263 MB，GitHub 直连只有 0.4 MB/s，放弃）
- 改用 **w64devkit 2.11.0**（65.6 MB 自解压 7z）：`D:\dafeiyu\downloads\w64devkit\w64devkit\bin\g++.exe`（GCC 16.2.0）
- 用现成的 `D:\dafeiyu\NapCat\7z.exe` 解开自解压包，**没有安装任何东西进系统**

编译命令：

```bat
g++ main.cpp -o 大肥鱼开关.exe -mwindows -O2 -static -static-libgcc -static-libstdc++ ^
    -finput-charset=UTF-8 -lshell32 -lws2_32 -lole32 -lgdi32 -luser32
```

> 注意 `-lgdi32 -luser32`：`-mwindows` 会默认带上，但编控制台调试版时要手动加，否则 `undefined reference to __imp_CreateFontW`。

## 4. 功能

| 按钮 | 行为 |
|---|---|
| 启动她 | 6185 不通 → 起 `start-astrbot.cmd`，最多等 90 秒；然后 `backend_state` 显示小号没上线 → 起 `start-napcat.cmd`，等上线（最长 90 秒）；期间若检测到 NapCat 日志出现二维码 → 自动 `ShellExecute` 打开 `扫码登录.html` |
| 关闭她 | `taskkill /F /T NapCatWinBootMain.exe` → 等 2.5 秒 → `taskkill /F /T astrbot.exe`；勾选项再关 `breeze-server.exe`、`ollama.exe` |
| 暂停开机自启 | 6 个自启项（AstrBot / NapCat / 掉线提醒 / 邮件提醒 vbs / Breeze / Ollama）从启动文件夹挪到 `D:\dafeiyu\startup-paused` |
| 恢复开机自启 | 反向挪回 |
| 状态区（每 3 秒刷新） | 大脑(6185) / 小号(探针) / 语音(8137) / 记忆(11434) |

命令行 `--selftest`：不开窗口，把四行状态 + 启动项位置写到 `D:\dafeiyu\docs\switch-selftest.txt`，方便脚本核对。

## 5. 迭代与踩坑记录

### v0.1 初版
写完 640 行，编译通过。自检模式放在 `WSAServer` 初始化之前。

**坑 1：自检全是 0** —— `--selftest` 在 `WSAStartup` 之前就调端口探测，`socket()`/`connect` 全部失败，四项状态打印为 0。
**修**：把 `WSAStartup` 提到 `WinMain` 最前面（自检分支之前）。

### v0.2 修子进程输出
**坑 2：重定向文件 0 字节** —— 用 `CreateFileW(..., nullptr, ...)` 建的句柄不可继承，子进程的 `hStdOutput` 指向一个无效句柄，python 的输出全丢。
**修**：`SECURITY_ATTRIBUTES{ bInheritHandle = TRUE }` 建句柄，并在 `CreateProcessW` 传 `bInheritHandles=TRUE` + `STARTF_USESTDHANDLES`。

### v0.3 修命令行
**坑 3：Python 把 `-X` 当程序名** —— 调用 `CreateProcessW(app=python.exe, cmdline="-X utf8 ...")` 时，命令行首 token 不是 exe 路径，CPython 解析成 `argv[0] = "-X"`，报 `can't open file '...\utf8'`。
**修**：`lpApplicationName = nullptr`，命令行第一项写完整的、带引号的 python 路径。
修完后 `dfy-state.json` 里拿到了正确的 `{"state": "up", ...}`。

### v0.4 修跨盘移动（用户实测发现）
**坑 4：暂停自启 6 项全部「移走失败」** —— 启动文件夹在 `C:\Users\...\Startup`，暂停目录在 `D:\dafeiyu\startup-paused`，**跨卷移动**时 `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)` 会以 `ERROR_NOT_SAME_DEVICE` 失败。
**修**：加 `MOVEFILE_COPY_ALLOWED`（两处：暂停、恢复）。
**同时改的**：失败时打印 `GetLastError()` 错误码，并分开「没找到」和「找到了但挪不动」，原来那句「启动文件夹里没找到她的自启项」是误导。

## 7. 已知限制

1. **强制结束**（`taskkill /F`）。理论上优雅退出对登录态更友好，但 NapCat 没有提供命令行退出；目前靠「关的顺序对」+「启动时检测二维码自动开扫码页」兜底。
2. 小号在线状态依赖 `backend_state.py`，它内部要跑一次探针（约 1–2 秒），刷新在 3 秒周期内可能显示上一轮结果。
3. 没有单实例互斥，双击多次会开多个窗口（功能不受影响，但会重复探测）。
4. `--selftest` 的 `dfy-state.json` 写在 exe 同目录；exe 放在只读目录会失败（不影响 GUI 使用）。
5. 没做图标、没做托盘、没做「开机隐藏到托盘」。
